## Deferred and legacy inventory

Custom-feed creation, CustomFeed and NewsFeed/Black-only presentations already exist in `ui/screens/home/`, but the current launch shell deliberately exposes Discover only. Their existing builders/gates remain intact; creation is **not newly exposed** by this redesign. The wizard's form inherits Theme and Pane, while filtering/sorting/entitlement logic is unchanged. Tests continue covering these components as deferred implementations, not claiming a shipped journey.

`OnboardingIntroScreen`, `OnboardingCustomFeedPrompt`, `ReadGate`/`FirstPostLockScreen`, the legacy `lib/screens/feed_screen.dart`/starter feeds, `ui/screens/mod/moderation_case.dart`, and `widgets/post_card.dart`/`PostInsightsPanel` are not imported into the current routed shell. They are not promoted to live routes. Existing theme consumers inherit the semantic theme; two stale onboarding screenshots were reviewed separately after the comparator fix. The old `LythausAppShell` now delegates to `AdaptiveShell` to avoid a competing navigation implementation.

No standalone saved-content route, direct messaging product, payment flow or operational Weekly/Monthly/Quarterly point-action API exists in this routed inventory. Nothing fictional is added. OS dialogs, provider-hosted authentication and the separate operator control panel remain supported external/native surfaces.

## Preserved contracts and exceptions

- Authentication, device integrity, session clearing, consent, role checks, server confirmations, API URLs, backend models and recurrence economics are unchanged. `/rewards` and `/settings` are additive paths; existing paths/query keys are retained. Browser/native back and tab query preservation have focused verification.
- User media remains unmodified. Semantic colors are centralized; fixed image dimensions, transparent hit surfaces and media-specific fit/crop settings are legitimate non-palette exceptions.
- Flutter currently follows `ThemeMode.system`. No separate app theme preference was invented or reset. Secondary-web preference uses its own isolated key.
- Available rewards can be redeemed only under the existing server eligibility contract. No points balance, awards, verification completion, partner discount or recurrence deadline is synthesized. Unavailable recurring periods appear after real offers/history.
- The production marketing root and all its source dependencies are frozen. The shared branding reference does not imply the app controls the homepage cascade.
- Native mobile hardware, camera/upload interruption, real auth/push/email, manual screen-reader operation and every possible live account state remain unverified. The automated and visual evidence must not be described as universal accessibility or production acceptance.
