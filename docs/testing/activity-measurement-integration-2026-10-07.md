## Contract, exclusions and visibility

The event grain is one authenticated account plus **server UTC date**, deduplicated by the PostgreSQL primary key. A naturally rendered visible foreground frame, including an empty feed, may submit the minimal signal. No timer, heartbeat, URL, viewed content, client timestamp, per-render history or new anonymous tracking is collected. Visibility is a client assertion, not proof of human attention.

DAU/WAU/rolling MAU use the latest 1/7/30 completed UTC days. Quiet is observed prior-30-day activity and no observed recent-30-day activity, with continuous consent and verified coverage across all 60 days. These remain proposed pilot definitions requiring owner acceptance. Each complete-window consenting cohort differs; currently held, inactive, deleted and production-acceptance accounts are excluded. Existing public contributors and registrations use their retained sources and are not divided by this pilot population. Existing Today/MTD/YTD posts, comments, comments-per-post and plan metrics are retained rather than rebuilt. Existing provider usage/cost/health gaps remain explicit; no new invoice, entitlement, billing estimate or provider binding is invented.

Owner-only aggregate responses contain counts, cohort sizes, window bounds, source and sample time. They expose no account identities or dates. The current actor is resolved by the actual Public JWT/token-version or Admin Access/membership dispatcher. The Admin response requires a committed audit; a fresh application UUIDv7 identifies each event, `actor_id` uses the canonical column, and the correlation remains text. Metadata contains only contract version and enabled status. The same existing public/admin rate limits apply. Analytics mutations invoke the existing origin/transport guard explicitly because the global origin helper covers auth routes only. Private responses are no-store.

Coverage starts unknown and is never inferred from row presence. A covered nonempty cohort can report measured zero. Missing coverage, no cohort, disabled collection, source/audit failure, capacity above 5,000 consent candidates and stale snapshots remain unavailable. Positive active observations may be labelled lower bounds during partial coverage; quiet never receives a partial count. The UI expires snapshots at 60 seconds or the next UTC-day boundary.

## Hold-safe privacy and retention

The normal metric horizon is 61 UTC dates. Expired dates stop contributing immediately and are disposed of by bounded scheduled cleanup; the notice does not promise that a scheduler proves instantaneous physical deletion. Existing legal holds preserve dates while excluding their accounts from analytics and preventing new collection or regrant. Withdrawal stops consent immediately and preserves held facts without counting them. The immutable `(user_id, consent_id)` ledger foreign key maintains account ownership across consent changes. After release, cleanup also removes unexpired dates from withdrawn episodes. Normal regrant removes previous unheld episode dates before restarting coverage.

Every destructive purpose function locks the account first, then all existing hold rows, including inactive rows, before deciding eligibility. The account lock fences new hold inserts through the canonical subject FK; hold row locks fence inactive-to-active updates. Contention raises a retryable lock failure and rolls the transaction back. The same rule covers record-day cleanup, withdrawal/regrant, expiry and DSR purge. Export includes preserved held dates with `retentionException: legal_hold`; it never exports hold reasons. DSR functions validate the authoritative request UUID, subject, request type and nonterminal state.

Jobs invoke purpose reconciliation in both native privacy Workflows, purge after the authoritative hold gate, attach the account-activity component before storing the passport, and clean up through native RetentionCleanupWorkflow. The same purpose-local cleanup uses the already configured fifteen-minute scheduled tick; no cron, provider or resource is created or changed. Each 500-row batch has a 1,500ms statement timeout. A run commits at most 20 batches and reports `activity_retention_backlog` if the bound is exhausted. Held accounts are excluded and rechecked under locks. An uninstalled pilot exports explicit `not_collected`; partial installation and the retained rollback marker fail closed rather than completing an incomplete export or deletion.
