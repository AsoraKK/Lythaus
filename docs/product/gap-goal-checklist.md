## Profile API dependencies still missing

- **Follower/following lists:** the authorized follow-status endpoint returns `following`, `followedBy`, and `blocked`; the existing POST/DELETE routes mutate one relationship. There is no follower/following collection endpoint, pagination contract, or list authorization response, so the profile exposes no list navigation or count.
- **Handle management:** `identity.handles` stores a unique normalized handle and signup can create one. The owner profile API reads it, but profile updates accept only display name and bio; no rename/reservation API or policy exists.
- **Avatar management:** `social.profiles.avatar_object_id` exists, but the profile API currently returns `avatarUrl: null`. No owner-authorized profile media attachment and serving lifecycle is available.

Profile edits retain explicit Save and return-later behavior, and setup stays skippable. The profile task does not add email/security editing, rewards/support activation, passkeys, a fifth tab, privacy-default changes, or deletion.
