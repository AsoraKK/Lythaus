## Profile API dependencies still missing

- **Follower/following lists:** current service exposes follow status and follow/unfollow mutations, but no follower or following collection endpoint, pagination contract, or list authorization response. The profile therefore shows no invented counts or list links. Add a server-backed list contract, including block rules, before adding navigation.
- **Handle management:** `identity.handles` stores a unique normalized handle and signup can create one, but there is no owner rename/reservation API or rename policy. The profile displays only a real returned handle.
- **Avatar management:** `social.profiles.avatar_object_id` exists, but the profile API currently returns `avatarUrl: null`; there is no owner-authorized media attachment/read-URL lifecycle. Keep avatar editing unavailable until that media ownership and serving contract exists.

The current owner profile continues to save only the supported display name and bio. Optional setup remains skippable, and profile edits retain explicit Save and return-later behavior.
