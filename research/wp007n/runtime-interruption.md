# Recorded Windows interruption

Arm A's first evaluation pass committed30 complete parent caches before a Windows `PermissionError` during atomic replacement of the persistent budget JSON. The attempt was reserved in memory before inference and the finalizer retained377 charged image-forward attempts for that run, including the ambiguous reservation. Its920.78seconds remain charged. This was an output-file sharing failure, not a nonfinite model result or a data/model change.

The telemetry observer and manual progress checks had been reading that same budget file while it was being replaced. Windows readers can temporarily deny replacement. This is the supported explanation, not a claim that the exact locking reader was uniquely identified. The observer now accepts a PID and samples only OS process counters after startup, without repeatedly opening the budget ledger. Manual budget reads stopped during extraction.

The frozen extraction/measurement code, model, cohort, thresholds and seed derivation were unchanged. The identical extraction command resumed: already completed parent caches are validated and skipped; the unfinished parent is recomputed with the same input-derived seeds. No forward/time charges or caches were erased. `run-A.json` preserves both the failed and resumed runs. The earlier four-parent replay and batch-equivalence certificate remain separate numerical checks; they are not described as the same interruption test.

This operational failure does not justify weakening the memory guard, scientific budget or atomic parent publication. No missing inference is converted into a low score.
